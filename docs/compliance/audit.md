## Part 1. Data inventory

### 1.1 Student data

Every student row belongs to one teacher's account (`students.teacher_id`, `backend: internal/database/migrations/000004_add_classroom.up.sql:30-40`), That's by design: TeachForFree is teacher-first, so teachers use it free with or without a school, and schools subscribe for the calendar, staff list, and admin features. Since 2026-11-14 a class can also belong to a school (`classrooms.school_id`), which is how the agreement defines the school's data. See "School classes" below, and F18.

Key: **Enc** means AES-256-GCM per field with a fresh random nonce (`cipher.NewGCMWithRandomNonce`). Each category has its own key, derived with HKDF-SHA256 from `STUDENT_DATA_ENCRYPTION_KEY`. Each ciphertext is bound (as GCM additional data) to its row ID and field name. **Plain** means stored as readable text.

### 1.4 Logging

- All logs are `slog` text to stdout (`backend: cmd/server/main.go:35`). There is no request or access logging middleware (`backend: cmd/server/api.go:257`). Retention is whatever Docker and Coolify keep.
- Every log key across the codebase is an ID, a count, a status, a route or path, or an error: `user_id`, `event`, `staff`, `section`, `link_id`, `notice`, `host`, `path`, `reason`, `err`, and so on. **No student names, note text, plan text, or event text reach the logs.** The push code says so explicitly (`backend: internal/push/service.go:228`). Invalid-input errors, which can quote user input, are never logged. Only unexpected errors are (`backend: internal/httpx/response.go:49`).
- Small exceptions:
  - The Resend error text is logged and stored in `failed` (`backend: internal/email/resend.go:157`, `internal/schoolevent/reminders.go:260,310`). It could quote a staff email address. It never contains student data.
  - The rate-limit log line records the IP or user ID (`backend: internal/ratelimit/ratelimit.go:189`). This is disclosed.
  - A malformed local `.env` makes `godotenv` return an error that quotes the bad line, and `main.go:50-51,39` logs it. Production has no `.env`, so this only matters locally.
- Logins are logged with `user_id` (`backend: internal/auth/service.go:180`), as are logouts (`:258`) and refresh-token reuse (`:236`). Failed logins are logged without the account or IP (`backend: internal/auth/handler.go:125-150`). Reads of student data and admin "acting for" views are not logged at all (`backend: internal/coteacher/middleware.go`).

### 1.5 Retention and deletion jobs (all hourly unless noted)

Expired refresh tokens (`backend: internal/auth/cleanup.go:31`). Deleted marks after 10 minutes. Substitute token copies after the day ends. Conference code copies after the last time, and whole conferences 30 days later. Co-teacher invite tokens and finished invites after 30 days. School join-link tokens. Push devices after 30 days and `push_sent` after 48 hours. Reminder-email rows 2 weeks after the date. Notices after 3 days.

School classes held after their teacher leaves are deleted 30 days later, with the students only in them (`backend: internal/school/cleanup.go`, `PurgeHeldClasses` in `internal/school/repository.go`). **Nothing else purges students, marks, lesson plans, or classes on a schedule.** Archived classes keep their history until the teacher deletes them. There is no account-delete route and no export route (full route list in `backend: cmd/server/coteacher_access.go`).

### 1.6 Caching

- **Server:** `Cache-Control: no-store` on every API response (`backend: cmd/server/api.go:257`, `internal/httpx/nostore.go`).
- **Website:** memory only. Nothing about students goes in browser storage.
- **Installed app only** (`frontend: src/main.tsx:101-105`): IndexedDB holds `me` (name, email, class names, the open roster), mark types, counts, `student` (name and classes only; not marks or notes), `groups`, lesson plans from yesterday to 7 days ahead, and calendar dots (`frontend: src/lib/persist.ts:40-59`). It's thrown away after 7 days (`:27,79`), never saved when signed out (`:91`), and wiped on sign-out (`frontend: src/lib/auth.ts:116`). The offline queue holds IDs and times only, for up to 30 days (`persist.ts:125-157`). Mark notes are never persisted: `student-marks` isn't on the list.
- **Service worker:** the app shell, JS/CSS/fonts, the logo, and sounds only. No API responses (`frontend: vite.config.ts:199-219`).
- **Substitute and family pages:** the link key lives in `sessionStorage` only (per the privacy page; consistent with `src/lib/sub.ts` not being on the persisted list).

### 1.7 Where student names appear unencrypted

1. In transit inside Cloudflare (TLS is terminated there) and in the API server's memory.
2. Teachers' devices: the screen, printed behavior reports with notes, and the installed app's IndexedDB (the roster, group names, and plans for −1 to +7 days).
3. Lock screens: push reminders show the subject title, which may contain a name.
4. Emails through Resend and in staff inboxes: event title, location, and notes, which the code itself expects may name students.
5. Substitutes' and families' browsers (the day's roster; a student's first name on the conference page).
6. Plain-text columns that teachers could type a name into: class names, mark-type labels, conference title and location, staff group, category, and break names.
7. Logs: **none found**.

## School classes (built 2026-11-14, uncommitted)

The user chose Option B on 2026-11-14: each class is the school's or the teacher's own.

- **Data.** `classrooms.school_id` (NULL: the teacher's own) and `classrooms.held_at` (the teacher left that school). `school_members.classes_asked_at` records the one-time "Which of your classes are part of this school?" answer. `backend: internal/database/migrations/000039_school_classes.up.sql`.
- **One visibility rule.** SQL function `class_visible(held_at, school_id, kind, viewer_school)`: the teacher sees all but held classes; a co-teacher sees the teacher's own classes, plus school classes only from inside that school; an administrator sees only the school's classes, held ones too. The scope rides in the request context (`backend: internal/classscope`), set by `coteacher.ActAs` from `cmd/server/space_lookup.go`. A missing scope sees nothing.
- **Enforcement.** Every route whose path names a class, student, mark or batch is checked by `backend: cmd/server/class_guard.go` (by pattern, so new routes are covered; `class_guard_test.go` checks every registered route). Lists, student pages, reports, daily counts, conference rosters, substitute links and `StudentsByIDs` filter with the same rule. Held classes are read-only for everyone.
- **Leaving.** Triggers on `school_members` hold the school's classes however the membership ends (leave, removal, staff-list removal, SQL) and give them back on rejoining. Held classes are deleted after 30 days; an administrator can delete sooner (`DELETE /schools/mine/classes/{id}`) or give a class back (`POST /schools/mine/classes/{id}/release`).
- **Contract end.** Deleting a school deletes its classes through `delete_classroom`, so students only in school classes don't linger.
- **Lesson plans** stay the teacher's (user decision); administrators never see them.
- **Tests.** `internal/classscope/checker_test.go`, `internal/school/classes_test.go`, `internal/classroom/school_test.go`, `internal/behavior/school_test.go`, `cmd/server/class_guard_test.go`; full suite passes. A browser walkthrough against a local test server passed 22 checks (join and choose classes, admin view limited, leave, held list, give back, delete).
- **Not built.** Export (CSV/JSON) of a school's classes, a button or script to delete a school at contract end, and moving a member teacher's school classes to the school before their account is deleted (deleting an account today deletes its school classes too).

## Initials or names-on-device mode (open decision; nothing built)

What a "server stores only random student codes" mode would touch:

- **Schema:** `students.first_name_enc` and `last_name_enc` are `NOT NULL`, 1-100 characters (000006:20-21). Codes or initials would need either a per-school flag that changes validation, or nullable name columns plus a `display_code`.
- **Server:** name validation and sealing (`backend: internal/classroom/service.go`, `repository.go:392-486`, `studentcrypt.go`). The Google import fills names from Classroom (`internal/classroom/import.go:131-185`); in codes mode it would have to hand names to the device instead of saving them. Every response that returns names (rosters, the student page, reports, substitute roster `internal/substitute`, conference family page `internal/conference/view.go:33,81`, school-admin views).
- **Device:** a local name map (IndexedDB, installed app only) keyed by student ID. It breaks on the website (no persistence by rule, `frontend: src/lib/persist.ts:16-22`), on a second device, for co-teachers, school admins, and substitutes (who would see codes), and on printed reports and conference notices, which print names.
- **Free text stays a leak:** notes, plans, and event titles can still contain names, so codes mode needs the in-app reminder too.
- **Notice to users:** a banner or email to teachers at schools without an agreement, plus privacy-page wording.
